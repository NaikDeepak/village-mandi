## Milestone Summary

**Key Decisions:**
- Enforce `UserRole` in API: Roles were treated as generic strings in the API client, now strictly typed.
- Optimistic check in `AuthProvider`: Prevents UI flicker during hydration.
- Mock Firebase Admin in server tests: Enables testing auth routes without real Firebase connection.
- Use renderHook for hook testing: Isolates hook logic in tests.
- Rebrand to Apna Khet: Transitioned to a more generic/scalable brand name.
- ReCaptcha V3 for App Check: Standard provider for web apps.
- Global App Check Header: Ensures all API calls are verified.
- Conditional App Check Enforcement: Allows monitoring vs blocking for safe rollout.
- Structured Security Metadata: Logs IP, UserAgent, and Path for security events.
- Items replacement strategy for order editing: PATCH /orders/:id replaces all items.
- Strict state machine for batches: `VALID_TRANSITIONS` constant defines allowed transitions.
- Cutoff validation at DRAFT→OPEN: Prevents opening batches past their cutoff window.
- JWT in httpOnly cookies: Prevents XSS token theft.

**Issues Resolved:**
- SEC-001: Added rate limiting to auth routes.
- SEC-002: Migrated to Firebase Auth (handled by Firebase).
- SEC-003: Migrated to Firebase Auth (handled by Firebase).
- SEC-004: Migrated to Firebase Auth (handled by Firebase).
- BUG-001: Wrapped checkAuth in try/finally to ensure loading state resolves.
- BUG-002: Migrated to Firebase Auth (handled by Firebase).
- SEC-006: Removed raw header logging.
- SEC-007: Implemented constant-time password check.
- UX-002: Verified/Cleaned up redundant UI in AdminDashboard.
- CODE-001: Removed duplicate comment in App.tsx.

**Issues Deferred:**
